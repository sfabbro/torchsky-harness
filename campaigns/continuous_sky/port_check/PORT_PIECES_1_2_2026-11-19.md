## 5. Piece 2: loader and instrument descriptions

`InstrumentDescription` (frozen dataclass in `torchsky.instrument`): name, telescope, aperture diameter, pixel scale per channel, detector names, `channel_of`, science-plane unit and `sky_factor(primary, science)` (the factor to MJy/sr from
header cards; same formula as the prototype's `to_sky_factor`), data-quality bit table class (the `IntFlag` classes already in the module), plane width in bits, default ignored bits and `dq_policy()`, detector terms
("stripes" for NIRCam), bandpass identifier prefix, extension names and `EXTVER` of each chip, WCS policy, minimum valid pixels, optional filter curves.
Facts moved from `instruments.py`: diameters 6.5, 2.4, 2.4 m; NIRCam pixel scales 0.031 and 0.063, WFC3/IR 0.12825, ACS 0.05 arcsec; default ignored bits 0 (NIRCam), 528 (WFC3/IR: hot pixel + bad flat), 80 (ACS: hot pixel + bit 64).
Bit 64 of ACS is "warm pixel" in the prototype's table but is not named in torchsky's ACS table (which names only certain bits), so it enters as the number 64.

`load_exposures(paths, instruments, sky_box, *, dq_policy=None)` in `_load.py`: identifies the camera from `INSTRUME` and `DETECTOR`; for each chip calls `field_observation_from_exposure_file(..., with_extras=True, mask_outside_box=True, sky_box=(lon, lat, half))`;
HST: replaces CRVAL, CRPIX, CD by those of the a priori alternate solution (the prototype's `hst_apriori_key` rule, fail closed when absent) and gives that header to the box test through `detector_to_sky`; multiplies `image` and `err` by the factor in float32
(as the prototype), recomputes `weight`; writes the bookkeeping cards (`TSINST`, `TSNAME`, `TSSPLIT`, `TSBOXRA`, `TSBOXDE`, `TSBOXHS`, `TSDETNX`, `TSDETNY`, `TSTOSKY`, `INSTRUME`, `DETECTOR`) because `FieldObservation` has no slot for them.
It uses one private helper of `exposure_io` (`_resolve_hdu`) to find the header of a given `EXTVER`: `torchfits.read_header` accepts only a name and returns the first chip.

Conversion (`_observations.py`): header solution evaluated with `torchsky.wcs.WCS` at every pixel and projected on the tangent plane at the box centre exactly as the prototype did (float64, stored float32); values, errors, mask, `cut0`,
detector shape, rotation and bookkeeping as the prototype's loader; filters indexed as the prototype (one instrument: digits of the name; several: pivot wavelength).

**Filter curves.** `torchsky.filter_profiles.bandpass_from_svo` falls back to the network (astroquery) and creates its cache directory when a curve is not cached, so a fit could reach the network. Smallest clean option chosen:
curves are tensors in the instrument description (`InstrumentDescription.with_filter_curves({band: (wavelength_um, transmission)})`); `load_exposures` copies them onto each observation (`transmission_wavelength`, `transmission_throughput`, `spectral_unit="um"`).
A missing curve makes `fit_sky` raise a clear error. A cache read helper could fill the tensors later.

### Real-file comparison (`compare_loaders.py`, output in `loaders.log`)

Box: the prototype's SMACS box, centre (110.8268, -73.4544), size 20.48 arcsec, data half side 11.24 arcsec (size/2 + 1.0). The two NIRCam files cover it. For HST the SMACS box is not covered by these files, so the box centre is the sky position of the
middle of the first chip of each file (from its own a priori header). The prototype side is its own loader (astropy readers, `data.load_exposure_file`), run only in this script.
Files: 2 NIRCam `_cal` (one long-wavelength, one short-wavelength chip), the first 4 of the WFC3/IR `_flt` files, the one ACS `_flc`.

| file kind | files, chips with data | cut, valid pixels | factor to MJy/sr | values on commonly valid pixels | sigma | mask | positions |
|---|---|---|---|---|---|---|---|
| JWST NIRCam `_cal` | 2, 2 | 496x498 (109,981) and 354x203 (33,500) | 1.0, equal | identical bytes (max diff 0) | identical | identical (0 differ) | identical float32; float64 difference 3.6e-15 arcsec |
| HST WFC3/IR `_flt` | 4, 4 | 252x225 (about 30,530) | 0.2472217087699703 and 0.2954675705140122, relative difference 0 | identical bytes | identical | identical (0 differ) | float64 difference 3.3e-10 arcsec; stored float32 positions differ by at most 9.5e-7 arcsec (one float32 step at about 10 arcsec) |
| HST ACS/WFC `_flc` | 1, 1 chip (EXTVER 1, CCDCHIP 2) | 544x571 (194,296 prototype, 194,287 torchsky) | 0.0047933896489418155, relative difference 0 | identical bytes | identical | 9 pixels differ, all valid only in the prototype; each lies inside the box edge by less than the position difference (the three closest to the edge are 0.3, 0.4 and 0.7 mas inside) | float64 difference 8.9e-4 arcsec (0.9 mas) |

Explanation of the ACS differences: the prototype uses astropy's WCS, which applies the look-up-table distortion of ACS (`D2IMARR`, `WCSDVARR`, keywords `CPDIS1 = LOOKUP`, `D2IMEXT`). `torchsky.wcs.WCS` applies the SIP polynomial but not those tables,
so positions differ by about 0.9 mas and nine pixels within the position difference of the box edge change sides. This exceeds the 1e-6 arcsec requirement for ACS; JWST and WFC3/IR meet it in float64 and are at float32 round-off in the stored arrays.
The second ACS chip has no pixel in this box in either loader, so the two-chip path (`EXTVER` 2) was not exercised on real data.

## 8. Approximations and shortcuts

1. The numerical code is moved as is: the region lattice (dead in value), `burn_reference_init` (do-nothing construction that keeps the random-number sequence), and the fixed six-term quadratic background stay.
2. `background_order` is a field that accepts only 2.
3. Held-out exposures must be in the list given to `fit_sky` (marked by header card `TSSPLIT = "held"`); `predict_exposure` cannot score an exposure that was not, because the fit's per-exposure tensors have one row per exposure. The plan's "any exposure" needs rows added after the fit.
4. Positions: ACS look-up tables are not applied (section 5). Without the `TSBOXHS` card the sky half-size is an approximation of the prototype's rule.
5. One tile; no `shifts_from` file, no `train_half`, no protocol splits, no dither groups from a file (the card `TSGROUP` is optional and unused by the fit); no MJD card (the fit no longer uses epochs).
6. `SkyFit.save` does not reuse `map/field/artifacts.py`: its manifest requires a registered field-model kind with validated constructor arguments and a `FieldDomain`, which an item sky with a response does not have. The layout is analogous (JSON manifest, tensors only, `weights_only=True` on load, atomic replace).
7. `SkyFit.response` is a small read-only view (kernel network, codes, `noise_terms()`); the plan's `kernel(...)` and `throughput(...)` readers are not implemented.
8. The HST a priori solution is chosen by the prototype's rule on `WCSNAME<letter>` cards; I checked that it picks alternate B in the real WFC3/IR and ACS files.
9. Loader mask: the file reader's usability test also requires `1/err**2` to be positive in float32; the prototype did not. Not seen to matter in the real files (masks identical).
10. The oracle script copies the prototype's synthetic records into torchsky's record type by field; it does not exercise `FieldObservation` conversion bit for bit (only the round-trip test does).

## 9. Where the source fights torchsky's rules

- `astropy.io.fits` (`read_exposure_file`, `read_nircam`, `read_hst`): replaced by `torchfits` through `field_observation_from_exposure_file`.
- `astropy.wcs.WCS` (class `AstropyWCS` for HST, with distortion look-up tables): replaced by `torchsky.wcs.WCS` on the a priori header; look-up tables lost (ACS, 0.9 mas).
- Network and cache filter curves (`bandpass.svo_filter`, `instruments.filter_curve`): replaced by curves as tensors.
- `argparse`, `SystemExit` for user errors, global module state (`DQ_IGNORE_BITS`, `HST_WCS`, `DQ_IGNORE_OVERRIDE`, `FILTER_CURVE`, `RATE_WCS`): removed from the moved code; `ValueError` instead. The two module variables of the item sky (`SPECTRAL_DOMAIN`, `ITEM_CHUNK`) remain in the moved code and are set and restored around every fit and prediction (`_module_state`).
- Hidden dependence on torch's global random generator: `fit_sky` seeds it with `config.seed` at the start (as the prototype's `main` did), so a fit changes the global generator state.
- Print-based logging replaced by a `log` callable (the moved code keeps calling it with one line at a time).
