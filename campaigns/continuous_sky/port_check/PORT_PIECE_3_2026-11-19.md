## 2. Design choices, with reasons

1. **`product` takes `observations=`; the fit keeps no reference to its training exposures.** Keeping them would pin the whole training set in memory for the life of the fit (about 8 million pixels, several gigabytes, on the real field), would not survive `save`/`load`, and would give loaded fits a second, different code path. With `observations=` a fresh fit and a loaded fit are the same case. Cost: the caller passes the same list again. Safeguards: observations are matched by `TSNAME`; held-out ones are ignored; every training exposure must be present once; the median error and median value of each exposure are compared with what the fit stored (relative 1e-5) so a wrong data set fails closed; the box-centre cards are compared with the fit's.
2. **Moved code is untouched; glue is separate.** `_uncertainty.py` is the prototype module with the command line, the FITS writer (astropy) and the file-based difference removed, `log=print` defaults replaced by a silent default, one unused assignment removed (ruff F841), and the formatter applied. `compare_uncertainty_source.py` compares the two as syntax trees: 29 of 30 top-level items identical; the only difference is `SkyNormalOperator._circ_q` (the unused assignment `N, c = ...` became `c = ...`). Kept: `difference_map` (the array-level half-difference), `alternate_groups`. All new logic is in `_product.py`.
3. **`resolution` is a full width at half maximum in arcsec** (the specification), the moved code works with the Gaussian standard deviation `s`: `FWHM = 2 sqrt(2 ln 2) s`.
4. **"Native" resolution** = per band, the median over the covered nodes of the prototype's supported resolution `s*(x)` (smallest Gaussian width from which alpha = -d ln sigma / d ln s is at most 2, scanned from coarse to fine on a ladder of 0.5 to 6 sky pitches). The prototype's "auto" does exactly this per band. One solve serves all bands; each band has its own native resolution (reported per band). The plan's "native = item floor width" (0.4 x pitch) was not used: it is a property of the sky representation, not of what the data support. When the ladder never settles, `"native"` raises `ValueError` and asks for an explicit resolution (the prototype would have smoothed with NaN).
5. **Output grid.** Default: the node grid (identical to the prototype). With `pitch_arcsec`/`region` the image is evaluated exactly at the output positions (the smoothing weights are separable); `std` and `valid` are interpolated linearly from the node grid (the prototype only had the node grid). `valid` = covered, finite, positive `std` (on the node grid); on another grid all four surrounding nodes must be valid. Noted in `notes`.
6. **Header** is built by hand with the same sign convention as `tangent_positions` (east to the left, X west along columns, Y north along rows), tangent point = box centre stored by `fit_sky` in `structure["box_centre_deg"]` (new key; older saved fits lack it and then CRVAL is 0, 0 with a note). Verified in tests by evaluating it with `torchsky.wcs.WCS` (`tangent_positions`) back to the node positions.
7. **`residual`**: the relative residual of the solve that the time budget cut; otherwise of the Gauss-Newton step (`nan` when no step ran). A solve cut before its first iteration gets 1.0 (the moved code leaves `nan` there; a one-line change in the glue).
8. **`half_difference` is public.** It is the plan's ship criterion for real data (disjoint-half test per band), and the user cannot run it without it. Pull = (a - b) / sqrt(std_a^2 + std_b^2) at the pixels valid in both; returns mean, rms, a global scale ratio, the count, and the pull map. Requires equal grid, bands, unit and explicit equal resolution. Owner to confirm it should be public (adds one name to the manifest).
9. **`predict_exposure` for an unseen exposure.** One row is added to a second `FieldOperator` built (inside `torch.random.fork_rng`) with the extended per-exposure metadata, its state is the fit's state with one more row for each per-exposure tensor (new row at the constructor's initial values: background constant = the exposure's median, all else zero), the sky and the response are shared and frozen, and then the existing `heldout_stage` fits the terms (cross-fitted on interleaved 4 x 4 blocks by default), and the existing `_predict_record` predicts. The route for exposures that are in the fit's list is unchanged code: the bit-identity check of the fit passes (section 4D) and the existing prediction test passes. The fit's state and the global random state are checked unchanged in a test.
10. **Readers.** `kernel`: bandpass-weighted mean over the filter's wavelength nodes of `taper(r) exp(l(v, h) - log Z)`, with `log Z` from the model's own quadrature function (`kernel_level_values`), the blur-gauge dilation applied, in the detector-aligned frame (the model's frame; no rotation), unit 1 / arcsec^2; default stamp half-size = min(normalisation radius, kernel extent) at the channel's render pitch. Flux inside the normalisation window is 1 to the quadrature accuracy (1.009 measured on the test fit; the test allows 2 per cent). `throughput`: published transmission at the `Q` nodes times `exp(gamma)` with `gamma` the learned log-throughput of an exposure with zero gain effect after the gauge; for the reference instrument the transmission-weighted mean of the log-throughput including the gains is zero at every node (tested to 1e-5). `noise_terms`: unchanged, documented. These add one small public NamedTuple (`KernelStamp`, not exported) because a stamp needs its pitch.
11. **Seed.** Draws use a private generator seeded 0 (the prototype's default), so a product is reproducible and does not touch the global random state. No `seed` argument (the specification's signature has none).

### B. Calibration in torchsky's own tests
`test_polished_product_is_calibrated_on_a_field_with_zero_sky` (59 s here with another job on the machine): a one-filter field (6 exposures, 24 x 24 pixels of 0.1", noise 1, fixed seeds) whose **true sky is zero** (the synthetic generator's truth replaced by an empty one), fitted by the public `fit_sky` (60 steps), product at 0.4" FWHM, circulant std, polished. Pull = (image + delta) / std over the valid pixels, with delta = mean fitted background - mean true background (the zero-level offset, as in the prototype's "total" pulls). Asserted: `std` finite and positive where valid; |mean| < 0.6; 0.4 < rms < 1.42; the polish-off sky is not asserted on.
Bounds from independent pixels: smoothing s = 0.17", correlation length about 0.2", about 25 independent elements in about 2" x 2": sd of the mean 0.2 (bound 3 sd), sd of the rms 0.14 (upper bound +3 sd).
**What it cannot support.** Measured on this field: mean +0.02, rms 0.54 to 0.57 (0.72 with 300 iterations, 0.54 with 4 posterior draws instead of the circulant std). So the calibration band of 0.9 to 1.1 is not met on this field and is not asserted: the 60-iteration Gauss-Newton solve on a small, poorly conditioned field has a relative residual of about 0.14 (the prototype's truth problem reaches 5.9e-4), and the circulant std assumes uniform coverage on a field that is mostly edge. The test asserts only that std is not understated (rms below 1.42) and not absurdly overstated (above 0.4); the comment says so.
I also tried a field with sources (3 point sources and 2 galaxies, same size): the pulls of the polished sky had rms 2.7 to 4.3 (mean consistent with 0 after the zero-level offset), because the response learned in 60 to 150 steps is not good enough (the prototype's truth problem freezes the kernel at the truth after 2500 fitting steps). That field cannot support a bound and no test uses it. **The calibration with sources rests on the prototype's measurements on its truth problem** (pulls of the polished sky rms 0.96 to 1.10 over the inner region, 0.9 to 1.2 at sources; half-difference over analytic std 1.00 +- 0.03), reproduced here bit for bit (A), not re-measured.

## 6. Approximations and shortcuts (all)
1. Everything in the prototype report (sections 2, 5 and 7): response, registration, gains, noise terms held; the sky modes degenerate with the backgrounds (constant, gradient, quadratic) and the zero level are not in `std`; item sky treated as a free grid at its raster; Huber weights; weak prior 10 node-noise units; 60 conjugate-gradient iterations (variance about 2 per cent low per draw).
2. Real-data adaptation of the prototype (section 9) is untested here (no GPU, no real data): peak memory per batch, time per pass, the iteration count at K = 12 with chip gaps; 64-pixel tiles versus 256-pixel tiles on real data.
3. Tiles: on CPU `product` always uses the pixel budget (`batch_pixels`); the prototype's CPU default (no budget, 32 tiles per render) is not what runs.
4. `std` and `valid` on a grid other than the node grid are interpolated linearly from the node grid.
5. The data check in `product` compares two scalars per exposure (median error, median value), not every pixel.
6. The polish needs the unconverged-solve caveat in the notes; a cut step is the last iterate.
7. Calibration is not re-measured on a field with sources (B).
8. The explicit FWHM resolution is converted to sigma by one division (1-ulp round trip).
9. `KernelStamp` is returned but not exported or listed in the manifest.
10. Draw seed fixed at 0.
11. The synthetic bookkeeping of the shared test helper: its `bkg0` is the all-pixel (lower) median, so the cached private fits cannot be used with `product` (hence the new `public_cached_fit`).
