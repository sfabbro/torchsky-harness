## 5. What was deleted, by group

1. **Grid sky.** The coefficient-grid sky (`SkyGrid`), its diagonal preconditioner and the positivity penalty, `--sky-form`, `--sky-precond`, `--sky-neg`, the grid-only parts of the warm start and of the tile code. The item sky is now the only sky and has its own `sample_coeffs`, `pooled` and `band_images` methods.
2. **Item rasteriser variants.** The `direct` rasteriser, the square patch shape (sheared patches only), fine patch buckets (coarse only), `--item-raster`, `--item-patch`, `--item-buckets`, the pedestal option of the rasteriser.
3. **Per-pixel quadrature and Keys interpolation.** `render_quad`, `quad_points`, `bicubic_read`, the non-batched `render_fft`, `crop_padded`, `--render`, `--interp`, `--quad-nrad`, `--quad-naz`, `--batch-render` (the batched render is the only render).
4. **Back ends and loader.** `tsky_backends.py`, `--item-impl`, `--loader`, the telescope-frame positions and `--rate-wcs`.
5. **Kernel variation** across the detector, with time, and the extra variation with wavelength (`--k-space`, `--k-time`, `--k-lambda`; `--k-exp` stays), the detector and epoch code networks and their reference lattices (`--ref-footprint`).
6. **Throughput fields** across the detector and with time (`--g-fields`, `--tau-g-max`).
7. **Distortion**, static and drifting, and the per-exposure distortion code (`--distortion`, `--tau-d-max`, `zD`).
8. **Detector pattern** (`--pattern-grid`), **gated non-linearity** (`--nonlin`), per-pixel **gain map** (`--pixel-gain*`, `--lr-gain`).
9. **Count-rate input** (`--input-level`, `--rate-units`, `--rate-photom`, `--rate-dir`, `rate_kappa`, the pixel-area factor, the per-pixel Jacobian) and the epoch coordinate (`--epoch-min-days`, `--epoch-axes`, `--epoch-per-instrument`, the fields `t` and `mjd` of an exposure).
10. **Learned filter shift** per (detector, filter) (`--filter-shift*`, `--lr-filter-shift`).
11. **Zero rules:** the masked zero rule and its refresh (`--sky-zero*`, `sky_zero_refresh`, `smooth_image`), the positivity margin (`--sky-positivity-margin`).
12. **Variability evidence:** validation dither groups (`--n-val-groups`, the `val` split), gradients of the scales, likelihood-ratio checks, caps, at-cap reports (`--variability-evidence`, `--val-nuis-steps`, `--lr-tau`, `--tau-beta`, `--tau-occam-z`, `--tau-warm-evals`, `--tau-code-max`, `--ab-every`, `--ab-beta`, `evidence_step`, `ablation_evidence`, `item_losses`). ## 9. Surprises, hidden couplings and shortcuts

- **The random number generator was the main hidden coupling.** The deleted modules (detector and epoch networks of the kernel code and of the throughput, the two distortion networks, the non-linearity embedding) were built with random weights from torch's global generator, between the modules that remain. Deleting them changes the initial weights of everything built after them and the generator state that the render jitter and the warm start use later. To keep check A bit-identical I kept calls to a do-nothing function `kernel.burn_reference_init(...)` at four places where the deleted modules used to be built (three in `FieldOperator.__init__`, one in `Codes.__init__`); each call receives the same constructors with the same shapes, so the generator advances exactly as before, and the modules are thrown away. **This is a deliberate shortcut**: about 10 lines of dead construction, explained in the function's docstring. If you delete these calls the package stays correct, but its random numbers, and so every fit, change, and the oracle files must be remade.
- **Parameter order matters.** `clip_grad_norm_` and Adam depend on the order of the parameters in a group; the surviving parameters keep their relative order. Empty Adam groups were removed (harmless).
- **The region lattice is dead in value but not removed.** With the kernel no longer varying across the detector, every node of a region has the same kernel, so the bilinear blend of region images does nothing in value. Removing it (and the region-node tables) would shorten `model.py` and `render.py` and save run time, but the blend weights add to one only up to rounding, so the states would no longer be bit-identical. It stays, and entry F14 of the list of approximations says so. This is the largest piece of code that I could not remove.
- **`--kernel-norm-radius` default.** The old default was "2 arcsec with several instruments, whole support with one"; the minimal model used 2.0 everywhere. The default is now 2.0 and `resolve_instrument_options` no longer resolves it (it still resolves `--gauge-ref-inst`). A run with one instrument and no explicit radius therefore behaves like the unpruned `--minimal`, not like the unpruned default.
- **A test failure that was a field effect, not a pruning effect:** `test_coarse_reg` first failed (held-out score ratio 0.68 against the 0.5 it asserts) because its synthetic field had 5 exposures per filter with one validation exposure, which now trains. With 4 per filter (3 train, 1 held out, as before) it passes; I did not touch the threshold.
- **Dead code that was not dead:** the `val` split label and `n_by_split` entries were read by the log line and the tile summaries; `rate_kappa` of the metadata was read by the splat warm start; `model.fs_on` was read by the coarse registration (its common-shift condition); `data.RATE_WCS` and `LOADER` by `uncertainty.py`. All handled.
- **`__init__.py`:** the list of approximations was rewritten (removed F3, F15, F37, F43 to F46; edited F2, F5, F7, F8, F10, F13, F14, F16, F19, F21, F22, F25, F27, F30, F31, F38, F40, F41). Numbers of deleted entries are not reused.
- **Other shortcuts:** the root-level notes were not updated; the results folders under `tests/` were kept except `gain_results`; `uncertainty.py`'s docstring was not touched; the synthetic-field and truth harness no longer reproduce the unpruned package's field exactly where a validation exposure was used (`n_val` removed from `make_field`, `make_field_tiles`, `build_field`).
- **Not run:** the truth problem (`tests/truth/run_truth.py`, 300 steps, several seeds) was run only as its smoke test; the long truth runs and the uncertainty calibration were not repeated. The numbers in `tests/oracle/results/truth_minimal_*` are from the unpruned package. No GPU run.
