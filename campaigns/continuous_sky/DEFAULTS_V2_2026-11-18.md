Words: *held-out exposure* = exposure never used in the fit; its per-exposure terms (background, affine registration, gain, codes, stripes) are fitted after the main fit.

## 4. Choices and approximations (the ones I had to make)

* **Block edges.** A pixel belongs to exactly one half, by its detector row and column, in blocks of 4 by 4 with no guard band. A fit on half 0 never uses the value of a half-1 pixel, but neighbouring pixels across a block edge share the point-spread response and any correlated noise (for example charge spreading), so the two halves are not strictly independent for edge pixels. The sky and operator are frozen in the held-out stage, so no information about the sky leaks through them.
* **Closed-form stripes with half the pixels.** `predict_exposure(..., fit_half=h)` zeroes the inverse-variance weight of the other half before the three alternations of row and column means; a detector row (or column) then has about half its pixels in its mean, rows or columns with none get 0. The written stripes for a pixel of half q therefore come from the other half's pixels of the same row and column (a 4-pixel run alternates with 4 pixels of the other half along every row). The stripe branch is NOT exercised by any test (the synthetic fields have no stripes and the NIRCam path needs real files); it is a one-line weight change.
* **Learned stripes** (`stripe_rows`, `stripe_cols`, the Adam-fitted ones) are fitted on the half as the other terms; priors are unchanged (`model.priors` applies to the same rows).
* **Cost and order.** The held-out stage is three nuisance fits and three predictions per exposure instead of one (synthetic fits, held-out stage: 18.9 s became 67.9 s for the grid fit and 19.6 s became 71.7 s for the item fit; the main fit also takes longer with `masked`: 23.6 s to 75.3 s and 138.9 s to 203.9 s). The all-pixel fit comes last so the saved state equals the old one.
* **Model-noise score.** Mean of ((data - prediction) / sigma_model)^2 over the same pixels, sigma_model = the model's `sigma(S)` at the prediction's sky signal; for the cross-fitted prediction S is also taken from the fit that predicted each pixel.
* **Noise-scale bound** is on the raw parameter, per (detector, filter) pair used by at least one exposure; unused pairs stay at 0. Bound check tolerance 1e-4 relative.
* **Two-instrument counting** is by the instruments among all loaded exposures (all splits), as asked.
* **`--legacy-defaults` leaves items 2 (and 4) alone**, as specified; to get the old two-instrument behaviour give `--gauge-ref-inst -1 --kernel-norm-radius 0`. Explicit `-1` counts as given.
* **Tests that predate this change** keep their old behaviour through `tests/conftest.py`, which makes `default_config` default to `legacy_defaults=True, gauge_ref_inst=-1, kernel_norm_radius=0.0` (a test can pass its own). One assertion had to change: `test_noise_floor_guard.py::test_bound_holds` expected no warning with the floor at its bound; it now expects the two new at-bound warnings.
* **State loading** assumes the same command-line options as the fit that wrote the state (the state file does not store the configuration). A different sky form, item count, pitch or number of exposures shows up only as ignored keys or ignored shape mismatches in the log; read that list. Plain attributes that are not tensors (variability scale modes, the positivity margin, sky-zero levels) come from the options of the loading run. The registration pre-pass is not rerun (its result is in the saved translations).
* **Zero start (item 5)** applies to the four nets named; the random kernel code (`hbar`, `hdet`, `hep`, audit A9 "0.3 rms") is not in the item and was not changed.

## 6. Not done, or not as specified, and open problems

* The 150-step item fit with the new defaults took 289 s in total (limit about 240 s; masked sky zero and the two extra held-out fits add to the old 200 s). It ran once, to completion. The item truth run took 237 s.
* Zero start side effect: the throughput and distortion fields are normalised by their rms over the reference set (`centred_normalised`, floor 1e-6 on the rms). At an exactly zero output the gradient of those four nets is about 10^4 times larger than at a random start (first batch, synthetic field: gdet 4.0e4 against 1.2, Dst 1.9e4 against 1.0), and the operator gradient clipping (norm 10) then scales every operator gradient by about 2e-4 on the first step; after the first step the normalisation turns whatever direction the gradient gave into a field of full amplitude (tau times unit rms). It did not stop any run here (finite everywhere, held-out scores similar), but it is a singular start; a start with an rms floor larger than 1e-6, or tau grown from 0, would be a design change I did not make.
* Stripes under cross-fitting: untested (above). Several tiles: `predict_merged` takes the cross-fitted predictor, but no multi-tile test of the held-out stage was run (the existing multi-tile test covers the fit only).
* `--heldout-only` was tested with a synthetic loader, not with real exposures or a state from a real fit; the check that the options match the fit that wrote the state is left to the reader (above).
* The cross-fitted held-out score still uses the all-pixel noise model and the frozen operator and sky; it removes the flattery of the per-exposure terms only, not any fitting of the sky to these pixels (the held-out exposures are not in the fit by construction).
* Item 3 asked for results "in the log and the metrics file": both done. The old `heldout_own` per-exposure entries now hold the cross-fitted numbers at top level (keys unchanged) with the old ones nested.
